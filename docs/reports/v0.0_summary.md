# v0.0：最简 loop，仅必要模块

**Code repo**：https://github.com/wujxy/SimpleLoop

## 基本架构

```
user goal → proposer (reads history, proposes a direction)
          → executor (edits code, delivers a commit SHA)
          → harness (computes diff + runs eval commands)
          → judger (grades the diff + eval output, gives feedback + score)
          → feedback feeds the next round's proposer
```

串行单 loop，一轮一次 proposer / executor / judger。无早停、无批处理、无并行、无 pareto / 池 / 审计 / 令牌账。round n 以 round n-1 的 commit 为 base（链式）；gate 拒绝或空轮不动链。harness 独占 commit 与 eval（确定性，不委托 LLM）；judger 只消费 diff + eval 输出打分。best = 历史最高分轮。剔除任何非必要组成：无 metric / 校验子系统、无独立 sandbox / context 模块、无 GEPA 方案迭代与并行化。

## 三个角色的交付契约

| 角色 | 输入（能看到的东西） | 交付格式 |
|---|---|---|
| **proposer** | goal、editable/frozen、全量 history（每轮 proposal+score+feedback）、cwd=源 repo（可 cat/grep/git log 只读） | `{"proposal": "<一个粗略方向>"}`，单 key，JSON-only |
| **executor** | goal、proposal、editable/frozen、cwd=worktree | 不返 JSON，只编辑文件；harness 读改动 → gate → commit → 返回 SHA |
| **judger** | goal、proposal、diff、eval 输出（命令 stdout + exit code）、rubric、cwd=worktree（可复跑验证） | `{"score": 0.0–1.0, "feedback": "<给下一轮的建议>"}`，JSON-only |

契约由 prompt 强约束（禁止 JSON 外的任何 prose）；proposer 解析失败时降级把 prose 当方向兜底，不浪费一轮；judger 的 score/feedback 严格校验，不合规记 failure 跳过、不炸 run。

## 基本模块（`simpleloop/`，约 1.1k 行）

- **loop** — 主循环：proposer→executor→eval→judger→store，链式串接，异常兜底（一轮失败不炸整 run）
- **agent** — `claude -p` 子进程适配，两态调用（JSON / 纯文本），超时与心跳
- **workspace** — per-run `git clone --local` 隔离 + per-round worktree + harness-owned commit + diff
- **proposer / executor / judger** — 三个角色各自的 prompt 与交付契约
- **config** — task.yaml 读取校验（严格 schema，未知键报错）
- **store** — append-only `history.jsonl` + best 跟踪 + 最终报告
- **gate** — frozen/editable 路径确定性检查
- **cli** — `simpleloop run` / `validate` 入口

关键取舍：per-run 物理隔离（每 run 一个本地 clone，源 repo 不动，可溯源）；harness 独占 commit（agent 只编辑不 commit，规避 LLM-commit 不可靠）；eval 在 worktree 里 harness 跑（确定性证据喂 judger）；确定性 gate 作安全网而非决策点。

## 小例子测试

`examples/tiny_algo_opt/` —— 一个故意慢但正确的 2-D 曼哈顿对计数函数，目标是降 ms/call 同时保正确。含 9 个精确计数测试 + 5 case 数值等价冻结基线 + 速度基准，三条作为 eval 命令由 harness 跑、输出喂 judger。

10-round 实测（test04.log，全部完成）：

| round | score | ms/call | 说明 |
|---|---|---|---|
| 1 | 0.92 | 3.80 → 2.03（~1.87x） | inline + 预拆坐标，micro-opt |
| 2 | — | — | proposer 返回 prose 非 JSON，记 failure 跳过（链不断） |
| 3 | 0.95 | 2.03 → 0.64（~3.2x） | spatial grid，算法级突破 |
| 4 | 0.50 | ~0.63（无提升） | correctness 绿但无实测提速，judger 压到 0.50 |
| 5 | 0.95 | 0.63 → 0.35（~9.6x over baseline） | 据 round4 feedback 修对称性，大赢 |
| 6 | 0.92 | 0.345 → 0.293（~15%） | cell size 调优，judger 独立复测确认超噪声 |
| 7 | 0.38 | ~0.305（轻微回退） | refactor 干净但实测小幅回退，judger 正确压低 |
| 8 | 0.90 | → 0.276（~2.3x over grid） | numpy 距离矩阵向量化，算法换轨 |
| 9 | 0.58 | ~无变化 | int16→int32 + radius<0 防御加固，无提速，judger 中分 |
| 10 | 0.92 | 0.578 → 0.506（~12.5%） | 减少 numpy 临时分配，judger 独立复测确认 |

收敛行为符合设计预期：judger 基于实测打分（不信单次 headline、会独立复跑 bench 验证），proposer 据 history 的 score/feedback 自我纠偏（round5 修 round4、round8 换轨向量化、round10 据 round8/9 feedback 优化分配），链式串接在失败轮后正确保持。最终 best = round3 的 commit（score 0.95，~3.2x；round5 同分但取先到者）。v0.0 端到端验证通过。
