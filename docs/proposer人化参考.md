# SimpleLoop Scientist Proposer MVP 重构设计

## 1. 目标

基于 `workspace-v0.2.0`，将当前 Proposer 从“Generator 产生 hypothesis、Cognitive 按 Sieve → Select → Enrich 加工”的流程式架构，重构为：

> **一个具有持续认知的 Scientist，在被交付 Goal 后自主研究问题，并根据自己的研究判断提出值得尝试的 proposals。**

这次重构的核心不是增加新的科学方法论，而是解决两个问题：

1. **Scientist Identity**  
   让 LLM 一进入上下文，就理解自己是这个研究问题的负责人，并自然调用模型已有的科研能力。

2. **Cognitive Continuity**  
   让多次独立的 LLM inference 在语义上仍然属于“同一个 Scientist 正在继续研究”，而不是每次重新唤醒一个新研究员。

本次不引入：

- Dewey inquiry workflow；
- G1–G9 强制生成元；
- Problem Representation schema；
- competing hypotheses 数量要求；
- UNDERSTAND / MODEL / EXPLORE 等 cognitive state；
- proposal merit gate；
- 科研行为自动评分。

这些能力后续只有在真实运行证明模型缺失时，才考虑作为 research disposition 或 optional skill 增加。

---

# 2. 当前基线需要改变什么

`workspace-v0.2.0` 的外围职责划分本身已经接近目标：

```text
Goal
  ↓
Researcher
  ↓
Executor
  ↓
Harness evaluation / gates
  ↓
facts / history
```

README 已经明确：Researcher 负责 investigation、interpretation 和“what to try”，可以提出局部修改、大规模重构甚至 replacement implementation；当前代码只是 starting artifact。Harness 才掌握 commit、evaluation 和客观事实。citeturn465650view0

因此这个边界应保留。

真正需要删除的是当前 Proposer 内部结构。

当前 `proposer.py` 仍然把角色定义成：

> Cognitive element for hypotheses generated by Generator

并执行：

```text
Generator
   ↓
HypothesisCard[]
   ↓
dedup
   ↓
Sieve
   ↓
Select
   ↓
Enrich
   ↓
Proposal
```

其中甚至规定 Cognitive selection 应基于 historical/source facts，而不是自己的 performance prediction。citeturn550211view0turn595490view2

这与新的 Scientist 定位冲突。

Scientist 必须能够形成自己的判断：

> “根据我目前对问题的理解，我认为这个方向最可能推进 Goal。”

它当然可能判断错误；Evaluator 负责告诉它现实结果。

---

# 3. 新架构

新的 Proposer 内部只有一个角色：

```text
                           Goal
                            │
                            ▼
                    ┌───────────────┐
                    │   Scientist   │
                    │ same persona  │
                    └───────┬───────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
      Workspace           Shell            History
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                    autonomous research
                            │
                 think / inspect / test
                 reconsider / pursue
                 change direction / ...
                            │
                            ▼
                       Proposals
                            │
                            ▼
                        Executor
                            │
                            ▼
                        Evaluator
                            │
                            ▼
                    empirical results
                            │
                            ▼
                  same Scientist continues
```

不存在 Generator 和 Cognitive 两个角色。

也不存在固定 Generate Phase / Cognitive Phase。

Hypothesis generation、调查、深化、reframe 都只是同一个 Scientist 在研究过程中可能自然发生的行为。

---

# 4. Scientist Identity

Scientist prompt 不应该写成科研 SOP。

它应该分成三种不同语义。

## 4.1 身份赋予

只在最开始明确一次：

```text
You are the Scientist responsible for this research problem.
```

这句话完成：

> model → Scientist

的身份映射。

---

## 4.2 导师教诲：描述“A Scientist 是怎样的人”

科研观和身份习惯主要使用：

```text
A scientist ...
A researcher ...
Research ...
```

而不是大量：

```text
You should ...
You must ...
Work like ...
```

例如第一版可以围绕以下语义：

```text
A scientist is responsible for making progress on the research
problem itself. Existing implementations and prior approaches are
resources for that work, not definitions of the problem or of the
solution.

A scientist develops their own understanding of a problem and forms
their own judgment about what may move the research forward.

A scientist investigates when understanding is insufficient, follows
ideas that appear promising, and changes their view when what they
learn no longer supports the old one.

Existing work deserves attention because it contains information and
experience, not because its structure must be preserved.

A useful solution may be a small change, a broad restructuring, a
different algorithm, or a replacement of the current approach. The
scale of a change is not itself evidence for or against it.

A scientist may reason boldly while remaining careful about what has
actually been established. Predictions and explanations are scientific
judgments; experimental results determine what actually happened.
```

这些句子描述的是：

> **科研人员这种人怎么看世界。**

而不是：

> 下一步执行什么动作。

---

## 4.3 世界事实

另外一部分使用客观陈述：

```text
The research goal defines success.

The workspace contains the materials currently available to this
research. Source code, existing implementations, notes, data, and
previous approaches describe what currently exists; they do not define
the solution space.

Experiment records describe what actually happened in previous
attempts. Interpretations of those results remain research judgments.

The Executor implements proposed directions.

The Harness owns authoritative evaluation, Gates, commits, and recorded
experimental facts.
```

这层建立世界中的权力关系：

```text
Goal                  → success authority
Harness experiment    → empirical authority
Scientist             → research judgment
Workspace / Prior     → research material
```

---

## 4.4 工具和运行规则才使用第二人称

例如：

```text
You can inspect and experiment with the research workspace through
the shell.

You can query previous experiments when they are relevant to your
research.

You may use the writable research workspace for analysis, probes,
temporary modifications, builds, and toy experiments. Research changes
made here are not candidate artifacts.

Submit the directions you currently believe should be tried through
submit_proposals.
```

这里使用 `You ...` 是合理的，因为这些确实是 runtime 在告诉 Scientist：

> 你拥有怎样的实验室。

---

# 5. Cognitive Continuity

这是本次重构最重要的 runtime 改动。

当前代码明确写着：

> continuity across rounds comes from Ledger / Finding / Frontier，而不是 Proposer round-local state。citeturn595490view1

新设计要改变这一点。

核心原则：

> **Call boundary must not become cognitive boundary.**

一次 Scientist research trajectory 可以包含几十次 LLM inference：

```text
LLM call
   ↓
tool
   ↓
LLM call
   ↓
tool
   ↓
LLM call
   ↓
...
```

物理上是多次 inference。

语义上必须是：

> **同一个 Scientist 一直在想。**

---

# 6. Scientist Session

每个 proposer lane 对应一个持久化的 `Scientist Session`。

概念上保存：

```text
scientist session
├── scientist identity / prompt version
├── goal
├── conversation trajectory
├── tool calls
├── tool observations
├── current workspace/base SHA
└── continuation memory      # 仅 context compaction 时使用
```

第一次启动：

```text
Scientist identity
+
Goal
+
World / workspace context
+
Tools
↓
first model call
```

之后绝对不要重新构造：

```text
Scientist identity
+
Goal
+
“previous researcher summary”
↓
new model
```

而是：

```text
existing Scientist conversation
+
new observation
↓
next model inference
```

模型看到的是：

> “我刚才做到这里，现在继续。”

---

# 7. Tool call 本身就是 Scientist 的生活经历

现有 Proposer 已经维护 `messages`，并把 assistant action 和 tool observation append 后继续下一次 model call；这一机制应保留并成为新 runtime 的中心，而不是被 Sieve/Select/Enrich protocol 驱动。citeturn760440view2

例如：

```text
Scientist:
I don't yet understand whether this state is rebuilt per hit.

Scientist → shell:
rg ...

Tool:
...

Scientist:
It is constructed inside the hit loop. That changes my earlier view...
```

下一次 call 必须看到这一整段。

这就是 cognitive continuity。

不需要额外要求模型：

> remember your previous reasoning.

上下文本身已经证明：

> 这是我刚刚经历过的事情。

---

# 8. Round boundary 也不应该自动成为人格边界

一个 round 完成以后：

```text
Proposal
↓
Executor
↓
Harness
↓
metrics / gate / accepted SHA
```

下一轮不应重新创建：

> New Researcher

而应该向当前 Scientist session 增加一个新的 world event：

```text
The experiment you proposed has completed.

Candidate ...
Result ...
Gate ...
Accepted revision ...
Current workspace is now based on SHA ...
```

然后继续：

```text
same Scientist
↓
“这个结果改变了我什么判断？”
↓
继续研究
```

因此：

> **Round 是实验调度单位，不是 Scientist 生命周期。**

如果当前有多个 proposer lane，则：

```text
Lane A = Scientist A + persistent cognition
Lane B = Scientist B + persistent cognition
Lane C = Scientist C + persistent cognition
```

每个 lane 内保持人格连续。

不同 lane 才是不同研究人员 / 不同 research trajectory。

这也为未来 tree/frontier 演化留下自然接口。

---

# 9. Context Compaction

不能假设整个 research trajectory 永远塞得进 context。

因此需要 compaction，但不能把 compaction 写成：

```text
Previous researcher summary:
...
```

否则人格会瞬间变成“接班”。

当 context 达到阈值时，应让**当前 Scientist 给未来的自己留下 continuation memory**。

例如 runtime 请求：

```text
Your research context needs to be compacted.

Leave a concise continuation memory for yourself so that you can
resume this same investigation without losing the understanding,
questions, judgments, and unfinished lines of thought that currently
matter.
```

输出可以是自然第一人称：

```text
I currently think ...

I originally suspected ..., but ... changed my view.

I still do not understand ...

The direction I was pursuing was ...

I was about to inspect ...
```

不要求固定 schema。

不要求：

```text
problem_model:
hypotheses:
unknowns:
```

下一次 context：

```text
Scientist Identity
+
Goal
+
Your continuation memory from earlier in this same research
+
recent conversation
+
current world state
```

这在语义上是：

> **我睡了一觉，现在继续自己的研究。**

而不是：

> 我接手了前任的工作。

---

# 10. World Memory 与 Scientist Memory 分离

现有 Experiment Ledger / Findings / Git history 应继续保留，它们属于：

## World memory

客观世界历史：

```text
candidate
SHA
metric
gate result
changed paths
experiment outcome
```

Scientist 可以查询这些事实。

---

新增：

## Scientist memory

用于 continuity：

```text
conversation trajectory
continuation memory
current intellectual direction
```

它不是权威事实数据库。

它只是：

> **这个人的研究经历。**

不要把二者混进同一个 history abstraction。

---

# 11. Tools：基本沿用现有基础设施

`workspace-v0.2.0` 已经提供 per-lane writable worktree，lane workspace 基于指定 `base_sha` 创建，Git 历史仍可访问。citeturn595490view3

因此无需增加复杂工具系统。

Scientist 第一版只需要：

```text
shell / run_research_command
history search
experiment inspection
finding/history lookup
submit_proposals
```

Shell 已经可以承担：

- 读源码；
- grep；
- build；
- profiler；
- toy experiment；
- scratch script；
- 临时改研究代码；
- 数据分析。

不必再人为拆出：

```text
inspect_source
make_model
run_probe
test_hypothesis
```

这些都是科研行为，不应该成为 cognitive tool taxonomy。

---

# 12. Proposal Interface

删除：

```text
HypothesisCard
→ select_for_enrich
→ one selected hypothesis = one proposal
```

Scientist 直接拥有 proposal slots。

例如本轮允许 `N=10`：

> 最多有 10 个实验名额可用。

Scientist 自己决定：

- 提几个；
- 哪些方向值得提；
- 一个机制提多个不同 intervention；
- 还是多个完全不同方向。

`N` 是容量，不是 diversity checklist。

---

Proposal 本身只要求让 Executor 理解：

```text
WHAT should be tried
WHY the Scientist thinks it may help the Goal
what important constraints must remain true
```

不要求 Proposer 把实现做到 line-level。

尤其应删除当前：

> “read until Executor can act without further codebase search”

这一约束。当前代码明确要求 Cognitive 深入到 Executor 无需继续搜索代码库，这会把 Proposer 推向 implementation planner。citeturn595490view2

Executor 本来就是 coding agent。

它应该能够：

```text
proposal
↓
自己读代码
↓
决定具体实现
↓
完成 candidate
```

因此 Proposal 可以是：

```text
局部函数修改
跨文件重构
数据流重组
算法替换
整个模块重写
```

它们在 Proposer 眼里没有先验等级差异。

---

# 13. Scientist 可以预测，但不能宣布事实

当前 Proposer 明确要求：

> select on facts, not predictions。citeturn595490view2

新版本应删除这一点。

Scientist 的工作本来就包括科学判断：

> “根据当前结构，我认为 A 比 B 更可能更快。”

这是合理的。

正确边界是：

```text
Scientist:
“I expect this to reduce runtime because ...”

Harness:
Actual result: 147 ms/event.
```

Scientist 可以：

- 预测；
- 判断；
- 排优先级；
- 相信一个方向；
- 大胆下注。

它不能：

> 把预测写成已经被实验确认的事实。

因此：

> **大胆判断，严格区分 judgment 与 empirical fact。**

---

# 14. History 的使用

History 不再通过固定 `NARROW` phase 注入。

Scientist 从第一刻就拥有 history query 能力。

但 startup context 不需要把整个 Frontier / Explore narrative 塞进去。

推荐：

### 自动提供

- Goal；
- 当前 accepted SHA；
- Gates / objective；
- 当前 workspace；
- Scientist 自己刚经历的实验结果。

### 按需查询

- 较老 experiments；
- findings；
- older diffs；
- previous attempts。

这样：

> history 是 Scientist 可以翻阅的实验记录，

而不是：

> 唤醒 Scientist 时别人先替它总结好的问题地图。

---

# 15. Budget

保留 agent step / token / timeout budget。

Budget 是计算资源限制，不是认知流程。

接近 budget 时只需要告诉 Scientist：

```text
The current research turn is nearing its computation budget.
If you have directions that you currently believe should be tried,
submit them now.
```

不要：

```text
You are now in the ENRICH phase.
Finalize your selected hypothesis.
```

Budget exhaustion 可以返回当前 proposals。

Proposal 不需要被证明成功才允许提交。

# 17. 建议的数据布局

概念上可以放：

```text
run_dir/
├── history.jsonl
├── memory/
│   └── ...
│
└── scientists/
    ├── lane-0/
    │   ├── session.jsonl
    │   ├── continuation.md
    │   └── meta.json
    │
    ├── lane-1/
    │   └── ...
    │
    └── ...
```

其中：

`session.jsonl`

> Scientist 的实际 conversation / tool trajectory。

`continuation.md`

> 只有 compaction 后才需要的第一人称 self-memory。

`meta.json`

只保存 runtime metadata：

```text
session id
prompt version
current base SHA
round
context version
```

不保存所谓 `problem_model`、`hypothesis_state` 等认知 schema。

# 18. 新的最小运行流程

最终 runtime 应简单到：

```text
Create / resume Scientist Session
            │
            ▼
      Scientist model call
            │
     ┌──────┴──────┐
     │             │
 research tool   proposal
     │             │
     ▼             ▼
 observation     return
     │
     └── append to same session
              │
              ▼
         next model call
```

实验结束：

```text
Executor / Evaluator
        │
        ▼
 empirical result
        │
        ▼
append world event to same Scientist session
        │
        ▼
Scientist continues
```

Context 满：

```text
same Scientist
     │
self continuation note
     │
compact
     │
same Scientist resumes
```

这就是完整的 MVP。

# 19. 如何验收

不要为“科研感”增加新的自动 Gate。

第一版主要人工观察 Scientist trajectory。

重点看：

### Identity

它是否真的把 Goal 当成自己的研究问题，而不是把任务理解成“输出 proposals”？

### Autonomous investigation

没有 Harness 强制要求时，它是否会因为“不懂”主动读源码、查历史、跑 probe？

### Independent judgment

它是否会形成：

> “我认为问题真正出在这里。”

而不是只复述已有代码和历史？

### Cognitive continuity

下一次 call 是否明显知道：

> 自己刚刚为什么查这个东西、之前相信什么、什么证据改变了判断？

尤其跨 round / compaction 后是否仍然像：

> 同一个人继续研究。

### Freedom

它是否能够自然提出：

- 小修改；
- 大重构；
- 新算法；
- replacement implementation；

而不会把现有代码形状当作隐式修改边界？

### Research dynamics

是否自然出现：

```text
不理解
→ 调查
→ 形成想法
→ 发现冲突
→ 改变判断
→ 深挖
→ proposal
```

而不是因为 runtime 要求才出现这些行为？

# 20. 最终原则

这次重构只坚持四条原则：

> **The Proposer is a Scientist, not a scientific workflow.**

> **The Goal belongs to the Scientist; the workspace and history are research material.**

> **Call boundaries are implementation details and must not become cognitive boundaries.**

> **The Harness provides the laboratory and empirical authority; the Scientist decides how to research and what should be tried.**

这版 MVP 的重点不是让 Harness 更聪明。

恰恰相反：

> **把 Harness 从 Scientist 的脑子里拿出去，让 LLM 已有的科研能力有机会真正工作。**
